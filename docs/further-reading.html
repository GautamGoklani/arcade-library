Further reading

Curated rather than exhaustive. Everything here is something I would actually send someone.

Specifications and canonical references

  • WebAssembly Core Specification — the actual document. Denser than you need for daily work, but the instruction index is the fastest way to settle "what exactly does this opcode do".
  • MDN: WebAssembly — the practical reference for the JavaScript API. Start here for instantiateStreaming, Memory, Table, Global.
  • MDN: Understanding the text format — the best free WAT introduction after this course.
  • webassembly.org/features — live proposal support matrix. Check before relying on anything post-MVP.
  • WebAssembly proposals repo — every proposal and its stage.

Books

  • Rick Battagline, The Art of WebAssembly (No Starch, 2021) — the only book that teaches hand-written WAT seriously. Closest in spirit to Part I here, and goes further on optimisation. If you want one book, this is it.
  • Brian Sletten, WebAssembly: The Definitive Guide (O'Reilly, 2021) — broader and shallower: ecosystem, toolchains, non-browser hosts, history. Good complement.
  • Kevin Hoffman, Programming WebAssembly with Rust (Pragmatic, 2019) — dated in specifics, still the clearest explanation of the Rust/wasm boundary and why wasm-bindgen exists.

Papers

  • "Bringing the Web up to Speed with WebAssembly" (Haas et al., PLDI 2017) — the original design paper. Readable, and the best account of why the format looks like this.
  • "Everything Old is New Again: Binary Security of WebAssembly" (Lehmann, Kinder, Pradel, USENIX Security 2020) — the honest treatment of what the sandbox does not protect. Background for chapter 12; read it before you trust a wasm sandbox with untrusted C.
  • "An Empirical Study of Real-World WebAssembly Binaries" (Hilbig, Lehmann, Pradel, WWW 2021) — what is actually deployed on the web, as opposed to what the marketing suggests. A useful corrective.

Tools

  • WABT — wat2wasm, wasm2wat, wasm-objdump, wasm-decompile. Chapter 9.
  • Binaryen — wasm-opt. Run it on everything a compiler produced.
  • wat2wasm online demo — live WAT editor with instant assembly and a JS scratchpad. The fastest way to try something.
  • wasm-feature-detect — runtime detection for every proposal, two lines.
  • wasm-tools — the Bytecode Alliance's Rust toolkit; the reference implementation for components.

Toolchains

  • wasm-pack and the Rust and WebAssembly book — the best-supported path, and the book's Game of Life tutorial is a genuinely good first project.
  • Emscripten docs — for porting C/C++. The "Porting" and "Optimizing" sections are the ones to read.
  • AssemblyScript — the gentlest on-ramp for a JS/TS developer.
  • Zig's WebAssembly docs — smallest sensible output, no hidden runtime.

Non-browser

  • Wasmtime — the reference standalone runtime.
  • WASI and the wasi specs repo — the system interface and its capability model.
  • Component Model documentation — the best introduction to WIT and composition.
  • Extism — make your own application pluggable with wasm; host SDKs for a dozen languages.
  • wazero — pure-Go runtime, zero CGO.

Game-specific

  • Glenn Fiedler, "Fix Your Timestep!" — the canonical treatment of the fixed-vs-variable timestep question from chapter 15. Twenty minutes, worth it.
  • Robert Nystrom, Game Programming Patterns — free online. The Object Pool, Data Locality and Game Loop chapters are exactly the design space chapter 16 operates in.
  • Craig Reynolds, "Steering Behaviors For Autonomous Characters" — the 1999 paper that the closest-approach dodging in chapter 17 descends from.
  • Marsaglia, "Xorshift RNGs" — the original paper, including the shift triples.
  • PCG — if xorshift is not good enough. The site's comparison of PRNG families is the best short survey available.

Talks

  • Lin Clark, "A Cartoon Intro to WebAssembly" — a written series, not a talk, and still the clearest explanation of how the format compiles and why it is fast. Read it first if chapter 1 went too quickly.
  • Lin Clark, "Standardizing WASI" — the same treatment for the capability model.
  • "WebAssembly: Building a New Kind of Cloud" — search for recent Bytecode Alliance conference talks; the component-model story is moving fast enough that a specific link would be stale.

Communities

  • WebAssembly Discord and the Bytecode Alliance Zulip — where the people building this actually are.
  • r/WebAssembly — low volume, decent signal.

If you are starting today

  1. Open the wat2wasm demo and write the sum module from chapter 2.
  2. Read Lin Clark's cartoon intro.
  3. Work through the Rust and WebAssembly book's Game of Life. You will write no WAT and learn the boundary, which is the part that matters.
  4. Come back to chapter 5 and lay out a struct by hand. That is the moment the model clicks.
