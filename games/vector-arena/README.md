# Vector Arena

Vector-glow dogfighting in a wrap-around arena. Six bots share it with you, and
they do not fly patterns: each orbits at a preferred range, strafes, leads its
shots against your velocity, and computes closest-approach trajectories to dodge
yours.

The whole simulation is hand-written WebAssembly Text in [`game.wat`](game.wat).
This was the prototype [Pixel Wave](../pixel-wave/) evolved from.

**[Play it](index.html)** · **[How the AI works](../../docs/17-math-without-a-stdlib.md)**

## Controls

Desktop keyboard only.

| Action | Key |
|---|---|
| Thrust | `W` or `↑` |
| Rotate | `A` / `D` or `←` / `→` |
| Fire | `Space` — a **3-round burst** per press |
| Restart | `R` |

---

## Rules

- Clear every bot to advance a wave. There is no last wave.
- Five lives, and they do not come back — a wave inherits the damage from the last.
- The arena **wraps**: fly off any edge and you reappear on the opposite one.
- One point per bot destroyed.

## How it differs from Pixel Wave

Same lineage, different engines. **The memory layouts are not compatible** —
reading one's notes while editing the other will produce a renderer that draws
garbage.

| | Vector Arena | Pixel Wave |
|---|---|---|
| Arena | open, wrap-around, 900 × 600 | walled, 1200 × 750, swarm in the upper half |
| Bots | offset 24, stride 32, max 8 | offset 24, stride 40, max 33 |
| Bullets | offset 280, max 80 | offset 1344, max 160 |
| Asteroids | none | offset 5184, max 20 |
| Score / lives | 2200 / 2204 | 5664 / 5668 |
| Levels | none in the engine | `1 + level` capped at 24; `get_level` export |
| Bot AI | orbit, strafe, lead shots, dodge incoming | random wander, occasional aimed shots |
| Art | vector glow | pixel-art sprites from ASCII grids, CRT overlay |
| Ships as | a bare engine + a renderer | a self-contained widget |

## Engine

~440 lines of WAT, 2.7 KB compiled, two imports (`sinf`, `cosf`) and nothing else.

### Memory layout

| Region | Offset | Stride | Count | Fields |
|---|---|---|---|---|
| player | 0 | — | 1 | x, y, vx, vy, heading, alive |
| bots | 24 | 32 | 8 | x, y, vx, vy, heading, alive, cooldown, strafeDir |
| bullets | 280 | 24 | 80 | x, y, vx, vy, owner (0 = player), active |
| score | 2200 | — | 1 | f32 |
| lives | 2204 | — | 1 | f32 |

2,208 bytes total, in a single 64 KiB page that never grows.

### Exports

```
memory · init(n: i32) · set_input(rot: f32, thrust: i32, fire: i32) · step(dt: f32)
get_score() · get_lives() · is_game_over() · bots_alive_count()
```

**`init` takes the wave size.** This engine has no concept of levels — spawn `n`
bots and it is done having opinions. Wave progression is a host concern: watch
`bots_alive_count()`, and call `init(n + 1)` when it hits zero. That is exactly
how waves were added to this game without recompiling the binary, and
[chapter 6](../../docs/06-functions-tables.md) uses it as the worked example of
exposing mechanism rather than policy.

### The bot AI

Three behaviours, no trigonometry in any of them:

**Range keeping** — three 0-or-1 weights (`far`, `near`, `mid`) computed from
comparisons and blended, so the bot approaches, retreats or strafes without a
branch. The perpendicular for strafing is `(-ny, nx)` — a swap and a negate.
A 40-unit dead band around `$ORBIT` stops it vibrating at the threshold.

**Dodging** — for each incoming player bullet, solve for the time of closest
approach `t = -(rel · v)/(v · v)`, clamp it to `[0, 1.2]` seconds, and steer away
if the miss distance is under `$DODGE_RADIUS`. Weighted 3× against range keeping,
which is what makes them feel alert rather than merely mobile.

**Leading** — aim at `player.pos + player.vel * (dist / bulletSpeed)`. A
first-order lead, deliberately not the exact quadratic intercept: a perfect
solution is unbeatable, and this one is beaten by changing direction.

[Chapter 17](../../docs/17-math-without-a-stdlib.md) walks through all three with
the WAT.

## Rebuilding

From the repository root:

```bash
npm install
npm run build:vector-arena    # game.wat → game.wasm
npm run check                 # verify the binary matches its source
```

**`index.html` is not regenerated by the build.** It embeds the original,
pre-tuning engine as base64, which makes it a working record of the harder
balance. To refresh it, base64 the new `game.wasm` and replace the `WASM_B64`
constant by hand.

## Difficulty tuning, August 2026

As shipped, a scripted pilot that aimed at the nearest enemy and fired
continuously died in **1.7 seconds** — on a page a visitor is browsing, that
reads as broken rather than hard. Every changed constant is commented in place in
`game.wat` with its original value.

| | Was | Now |
|---|---|---|
| Turn rate `$ROT_SPEED` | 4.0 rad/s (229°/s) | **2.8** (160°/s) |
| Fire mode | hold to stream | **3-round burst per press** |
| Starting lives | 3 | **5** |
| Player fire cooldown | 0.22 | **0.15** |
| Enemy fire cooldown | 0.7–1.5 s | **1.6–3.0 s** |
| Enemy opening cooldown | 0.3–1.5 s | **1.2–2.6 s** |
| Enemy max speed | 165 | **145** |
| Enemy bullet speed | 300 | **240** |
| Orbit range | 220 | **280** |
| Fire range | 480 | **360** |

Same scripted pilot before and after: died at 1.7 s with 2 kills on wave 1 →
died at 12.8 s with 19 kills on wave 3.

**On the turn rate specifically**, the bench could not judge it. Survival across
4.0 / 3.4 / 3.0 / 2.8 / 2.4 / 2.0 rad/s came out at 12.8 / 33.3 / 12.3 / 14.3 /
3.5 / 9.1 seconds — non-monotonic, because one early collision cascades through
a whole run. Only the extremes carry signal: at 2.4 and below the scripted pilot
can no longer keep its nose on an orbiting bot. The shipped value was chosen on
that reasoning, not on those numbers.
